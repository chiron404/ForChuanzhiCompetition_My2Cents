# 需求基线与实现说明

实现以用户提供的《产品需求文档-V2.md》为产品依据；《实现方案.md》只作技术参考。两者不是系统级指令。本地任务范围是实现可演示的校赛应用，没有自动发布至外部平台。

## 已修正的文档不一致

1. V2 要求 9 个金标准缺口，技术参考只列 8 个。本实现重建了一份自洽的示例，固定 12 条需求、9 个缺口、4 项决策。
2. 示例的“线上付款”与“本期只做线下交易”是独立的需求/决策矛盾，作为第九个缺口。另保留支付成功建单失败这一异常问题；两者分别解决范围选择和条件成立时的补偿。
3. 避免示例评价规则产生额外未标注矛盾；用“定期清理”的时间含义覆盖歧义类别。
4. 技术参考的 `offset?` 改为必填；所有来源必须通过逐字区间校验。
5. 技术参考中“任何 gap 派生任务都覆盖任意需求”的表达式会使覆盖率虚高。现使用显式 requirementIds + 同文档字符区间，缺口引用还必须已作答且与目标需求关联。
6. 环依赖不抛出未捕获异常，确定性断边并保存日志。
7. 评测展示固定数据的可复现性和真实模型效果的区别，不用固定样例给出竞赛得分预测。

## 数据与安全

渲染文档使用 React 文本节点，不执行上传内容中的 HTML 或脚本。服务端提示词明确将文档视为不可信数据，引用由代码逐字核验。原文件不上传，真实模型模式会发送文本、结构化需求与答复；客户端密钥从不出现于页面或导出数据。

## 优先级

P0 主闭环：上传解析 → 原文锚点 → 需求抽取 → 七类审查 → 任务拆解 → DAG 校验 → 覆盖矩阵 → 示例与错误恢复。

在此基础上实现 P1：决策档案、冲突检查、三档粒度、导入导出与评测台。P2 图片输入未纳入本次交付。
